# safe-refactor-sweep

Catches the one refactor failure class that ships real bugs here: a rename/refactor
that compiles clean (`tsc --noEmit` green, CI green) but breaks at runtime, because
the stale references live where the type-checker cannot see them.

## Why tsc lies about this

- Prisma's recursive `WhereInput`/`create`/`update` typing is relaxed. Stale or
  extra field names in `where`/`create` type-check and only throw at query time. A
  past field rename left **77 `create`-call sites** broken — all compiled clean,
  failed only when tests/seeds ran (~90 min cleanup).
- A rename shipped a **live bug to `main`** — tsc clean, CI green — because the stale
  references lived in: jest mock accessors (`mock.calls[0][0].create.oldField`),
  hand-written client types mirroring API JSON, and one of three separate test roots.
  None of those are visible to tsc.
- `git rebase`/`merge` auto-merge silently kept a pre-rename field name on a line
  adjacent to main's independent rename of the same concept. tsc saw a valid file.

## The checklist — run every step, in order

All commands run from the repo root unless noted. `<OLD>` = the old field/model/route
name; `<NEW>` = the new one.

### 1. Regenerate the Prisma client FIRST — unconditionally

```
npx prisma generate --schema checkin-app/prisma/schema.prisma
```

Do this before any grep or type-check. A stale generated client (common after a
rebase) produces false-positive AND false-negative type errors. Regenerate first so
everything downstream reads the real schema.

### 2. Grep the old name repo-wide — across ALL THREE test roots

This repo keeps tests in three disjoint roots. A rename sweep that misses any one of
them leaves stale references tsc never sees:

- `checkin-app/src/**/__tests__/`
- `checkin-app/tests/`
- `checkin-app/__tests__/`

```
grep -rn '<OLD>' checkin-app/src checkin-app/tests checkin-app/__tests__ checkin-app/prisma
```

Rules:
- **Never** `grep -v test` / never exclude test files — the live-bug references were
  IN test files.
- **Never** scope the grep to only the dirs you edited — even for a deliberately
  "sliced" rename. Cross-dir consumers (a route or wire-key used two dirs over) break
  silently; tsc is blind to string-held/some-literal `where` clauses.
- Use `grep -r` (recursive). A `git grep -- 'dir/*.ts'` pathspec does NOT recurse into
  nested dirs and gives a false "zero stale" result.
- Grep must reach zero (after accounting for legitimate unrelated matches) before
  moving on.

### 3. Grep the tsc-blind classes explicitly

These compile green with stale names and break at runtime. Grep each on its own:

```
# jest mock assertions / fixtures / inline literal test objects
grep -rn '\.mock\.calls\[\|mockResolvedValue\|mockResolvedValueOnce' checkin-app | grep '<OLD>'
grep -rn '<OLD>' checkin-app/src checkin-app/tests checkin-app/__tests__   # re-scan literal test objects

# hand-written client types that mirror an API JSON shape (not generated by Prisma)
grep -rn '<OLD>' checkin-app/src/types checkin-app/src --include='*.ts' --include='*.tsx'

# security config — an FK/relation rename touches this file, tsc-blind
grep -n '<OLD>' checkin-app/src/security/scopeBindings.ts
```

An FK/relation rename also tends to break `scopeBindings.ts`, the generated
classification mirror (`checkin-app/src/security/generated/`), security test oracles,
and frontend response mocks — all invisible to tsc. Only the full integration/CI run
surfaces them (see step 4).

### 4. tsc green is necessary but NOT sufficient — integration suite MUST run green

Do NOT report the task done on a green `tsc --noEmit` alone. Block "done" until the
integration suite has actually RUN and been observed green:

```
npm -w checkin-app run test:integration
```

This resolves to `INTEGRATION_DB=1 jest --ci --testRegex "\.integration\.test\.[jt]sx?$"`
(~22 integration tests). It requires a **live Postgres**.

**LIVE DATA — never point it at the real DB.** Use a throwaway/test Postgres. Seed it
with the built-in seed, never hand-rolled SQL:

```
npx tsx checkin-app/prisma/seed.ts
```

Prisma's recursive typing means integration tests are the real net for stale
`where`/`create`/relation-filter references — run them, watch them pass, THEN report.

## Worktree caveat

If you are running inside `.claude/worktrees/`: worktrees have no `node_modules` —
run a real `npm install` in `checkin-app/` first (do not symlink), or jest/prisma
won't resolve. If you invoke jest by hand, confirm it collected a nonzero test count
before trusting the result. No output for 60s+ usually means wrong scope,
not success.

## Done criteria

- [ ] `prisma generate` re-run before anything else
- [ ] `<OLD>` greps to zero across src + prisma + all three test roots
- [ ] mock assertions / hand-written client types / `scopeBindings.ts` explicitly checked
- [ ] `tsc --noEmit` green (necessary, not sufficient)
- [ ] `test:integration` observed green against a throwaway seeded DB (never the real DB)
